The journey, value × uncertainty, across all fourteen

Eight stages × fourteen competitors = 112 cells, all drawn. For the six profiled, each rated cell carries BOTH a capability rating (Strong / Adequate / Weak) and a confidence tag (High / Medium). Confidence is a dashed border, not a colour change — a Medium-confidence cell is the identical fill as its High-confidence counterpart, so a weak signal never has to borrow a stronger cell's colour to be legible, and a reader scanning for “how dark” is never told two different things by the same shade (see validation.md §3 for why v2's colour-blend approach could not do this on this token set). Grey, hollow, bordered cells mean no rating exists at all — not a weak one — whether that is because this specific stage was never reached for an otherwise- profiled competitor (○ unk), the competitor was never evaluated at all (○ n/e, the same 8 rows as every other section), or the evidence is prior-art only (◐ p-a, Kayak/Skyscanner). Meta

Corrections made from v2 to v3, each verified independently before being acted on

  1. Denominator rebase (Blocker 1 / correction C-034). v2's cluster chart and journey grid were denominated on the six profiled competitors (330 and 48 cells) while the KPI band above them was denominated on all fourteen (770 and 112) — the two objects said opposite things about coverage. Every chart now renders all fourteen rows and stacks or borders the eight unreached exactly as they occupy rows in the fourteen-row table, per [D-001]. Verified: the ten cluster percentages against all 14 sum to 581/770 = 75.5%, the exact complement of the 24.5% KPI; the journey grid draws all 112 of its own 33% KPI's denominator, not 48 of it.
  2. VSUP inversion (Blocker 2). v2 blended a value colour toward a grey uncertainty target with CSS color-mix(). Two independent audits found the result interleaved with the absence fill by luminance (teal-90 Y=0.0195 sat 1.30:1 from gap-80 Y=0.0407 — the study's single best rating and its total- unknown fill were near-indistinguishable near-black squares in the same table). The root cause is structural, not a bad colour pick: design-system/tokens/tokens.json is a Carbon mirror in which every hue family shares one universal lightness ladder, so any two ordinal colour ramps drawn from it at matching step numbers are luminance-identical regardless of hue (measured across seven hue families, §3 below) — there is no non-colliding third ramp to reach for on this token set. v3's fix does not try to find one: value stays exactly on three validated, unblended teal steps (60/70/90, never mixed, never dependent on confidence); confidence moves on a dashed-border channel instead of a colour channel; and absence, inside this one grid only, is drawn hollow rather than filled, so it is never a competing dark swatch in the first place. Verified by recomputing the luminance of every rendered fill in this grid: none are teal-vs-gap adjacent, because gap is never a fill here (§3 below has the full table).
  3. Print (Blocker 3). print-color-adjust: exact and its -webkit- prefix are now set globally. This is reasoned from the CSS specification, not confirmed on the interactive Print-dialog path a human would actually use — see §6 for what was and was not tested this session.
  4. Two disclosures promoted to the static flow (Blocker 4 / DC-04). Google Travel's “signed in, not like-for-like” and Tripadvisor's “the prompt was not typed” both sat behind a click while qualifying the board's single verified Yes and its most-confident row respectively. Both are now visible body text at point of use, with the click-through note kept only for the fuller citation.
  5. Accessibility (F-01, F-08). .gapnote's opacity:.86 is removed — it faded the whole element (stripe and text together) toward the page ground rather than toward the visible stripe, resolving to 3.85:1 on the lighter half of two rows. Every <summary> now carries a real, static text label (“evidence”) instead of relying on CSS ::before generated content as the only accessible name.
  6. Semantics (F-05, F-06, F-09, F-11). All four tables now have a real <caption> (the fourteen-row table's caption carries the exculpatory sentence that D-001 needs to survive a crop — previously it sat once, at 12px, outside the table). Row-identifying cells are <th scope="row">, not <td>. A real <h1> exists. Substantive content is wrapped in <main>.
  7. Token gate (DC-06 / A-4, corrected with nuance rather than deleted outright). The critique asserted tokens.json shows these primitives' Gate A as cleared and that A-4 is simply false. That is true of one place in the file: a batch-level note dated 2026-09-02 reads "Gate A — APPROVED by Agentic Designer - RP, 2026-09-02". It is not true of the primitives' own individual entries: palette.bone.default, palette.ink.default and both palette.coral roles each still carry their OWN gate field reading "Gate A — suggested by token-keeper; not counted until a human approves", unchanged since 2026-08-31. The file disagrees with itself at two different levels of specificity. This board treats the primitives as approved (the newer, more specific, dated record) but states the disagreement rather than picking a side silently — token-keeper's file, not this board's call to resolve.
  8. Class collision (DC-12), glyph vocabulary (DC-13), off-token size (DC-14). The chart's percentage label is now .pct, not a second .val. The scoreboard's two settled tests use ●, matching the completeness glyph already used in the fourteen-row table, instead of a ✓ that meant the opposite thing in the spotlight twenty lines above. The hero's /14 is --fz-h2, not an inline 0.5em.

Corrections made to the v2 brief (unchanged from v2, carried forward)

Two, both load-bearing, both checked against the cited paper rather than taken on trust.

  1. Song & Szafir (2018) supports the loud-blank redesign, but not with the margin the brief states. Verified against the PDF directly.
    • True: highlighting scored highest on perceived quality; the paper's own conclusion lists this first.
    • False as stated: "alpha-blending scores lower." The paper's own gradient-bar condition — alpha-blended, its own downplay category — scored consistently high on perceived quality in the bar-chart experiment; the authors flag this as a partial contradiction of their own hypothesis, not a clean result.
    • False as stated: "information removal scored lowest of every condition." In two of the four sub-studies (line-graph trend; bar-graph trend), an annotation condition — disconnected/point error bars — scored lower than the remove-the-data condition. Removal was consistently low, not always lowest.
    • Overstated: "caused measurably wrong answers." Visualisation type had a significant effect on accuracy in exactly one of four sub-studies (bar-graph averaging); line-graph accuracy showed no significant effect of visualisation type at all, in either task. The paper's own discussion calls the accuracy mechanism a hypothesis needing future testing, not an established result.
    • Domain mismatch, unremarked in the brief. The study concerns imputed points in continuous time-series charts (interpolated, zero-filled, or mean-filled Tweet counts). This board has no imputation and never estimates a plausible value for a gap (D-001 forbids it) — the transfer is by analogy (highlight vs. downplay vs. removal as a design choice), not a literal replication.
    What survives, and what this board acted on: highlighting beat removal with the least qualification of any finding in the paper, and the authors' own mechanistic account is about visual weight (opacity/coverage), not colour per se — their lowest performers "reduce or remove the weight of imputed" marks. That is what this board's loud blanks do: full opacity, full footprint, no thinning.
  2. The 330-cell (and 10×6) value×uncertainty matrix does not exist in ART-012 at cell resolution. ART-012 gives ten cluster-level Unknown counts (a single scalar per cluster — uncertainty only, no per-competitor value) plus scattered anecdotal single-cell mentions. Building a 10×6 grid would require inventing 54 of 60 cells; forbidden. The one place a true per-cell value×uncertainty pair exists, complete, for every profiled competitor, is the 8-stage×6-competitor journey table and the 6-cell load-bearing row — both rendered above, now extended to all fourteen rows by drawing the unprofiled eight hollow rather than by inventing values for them. The 10-cluster bar chart stays, correctly labelled as what it is: a single-axis gap-density view, not a bivariate.

What this board does not do

  • Does not carry the market findings, white space, or opportunity scoring (ART-012, not re-rendered here — Phase 11's job to interpret).
  • Does not verify against a live competitor product; does not research the eight unprofiled competitors — inventing a figure for any of them is the exact defect D-001 exists to prevent. Drawing them as hollow, unrated rows is not inventing a value; no capability rating is asserted for any of the eight anywhere on this board.
  • Does not open research/sources/; every citation is [ART-nnn § Section], never the artifacts' own [S-nn] register.
  • Does not judge the study. F-01 is reported as arithmetic fact; whether the recommendation should proceed while test 3 is unrun is a Gate A question for a human, not this board.
  • Does not resolve whether the coral disclaimer bar competes with the coverage headline for a reader's attention (DC-11, a judgment call, not an error). It is kept, deliberately: Bach et al.'s guidance is that a disclaimer belongs beside the number it taints, and every number it taints sits directly above it. This board accepts it may carry two headlines on first read and records that as a conscious choice, not an oversight.

  • A-2. The cluster gap-density sort (worst-first) and the fourteen-row order (ART-011's own) are this board's editorial choices, stated rather than left to a control — Aisch & Tse: sort order is a decision, not an interaction.
  • A-3. Row-state, tier and journey classifications are drawn from ART-011/012 verbatim, not re-adjudicated here. The eight unprofiled competitors' journey and cluster cells are drawn hollow/structural by construction (D-001), not because ART-012 states a value for them — it does not, and none is claimed.
  • A-4 (corrected, see the numbered correction above, not deleted). Colour values are read from token release 0.2.0. The release's own primitive entries for bone/ink/coral still carry a per-token "not counted until a human approves" string that a separate, newer, more specific batch note supersedes with an APPROVED dated 2026-09-02. This board treats the values as approved but does not paper over the file's internal disagreement.
  • A-5. The per-cluster row counts used to compute the full-14 denominators (rows × 14) are read directly from [ART-012 § The feature matrix] ("55 feature rows across ten clusters: vertical coverage (7 rows), decision support (10), ..."), not inferred by dividing each cluster's six-competitor cell count by six — the two methods agree exactly (cross-checked, all ten rows), but the direct reading is the one cited.
