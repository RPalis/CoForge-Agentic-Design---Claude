These totals are a floor, not a measurement

The ledger says so itself. Quoted verbatim from its completeness block, because a cost figure that looks complete and is not will misprice every decision made from it.

  • Nothing before 2026-09-01. “Dispatches before 2026-09-01 are NOT recorded — their usage blocks were consumed in conversation and are unrecoverable. Several 2026-09-01/02 runs are also missing: only rows whose exact usage block could be quoted are entered, and a run recalled but not quoted was left out rather than estimated. Totals below are therefore a FLOOR, not a measurement.”
  • The orchestrating session is absent. “Main-session cost is not here at all. Only subagent dispatches return a usage block; the orchestrating session's own tokens are invisible to it. The true cost of this work is higher than any total this file can produce, by an unknown margin.”
  • Hand-entered, not collected. “It is append-only and hand-entered from each dispatch's own returned usage block — there is no API to collect it from, which is stated rather than pretended otherwise.”

Outcome is not a pass/fail axis

“One row per dispatch, entered when the dispatch returns. `outcome` records what the run DID, not whether it succeeded — a refusal that caught a real defect is a successful run of an attestation and must not read as a failure. Cost without outcome is a number nobody can act on.”
— validation/agent-runs.json § the_rule

The field takes four values — found-defect, delivered, refused, attested — and none of them is “failed”. The 2 refusals each carry a found entry beginning “REFUSED.”; both are in the table below, verbatim. What this board cannot tell you

  1. Any cost before 2026-09-01. The ledger begins at 2026-09-01; earlier usage blocks “were consumed in conversation and are unrecoverable”. The count of missing dispatches is itself unknown, so the gap cannot be sized.
  2. The runs that were left out. The ledger records that several 2026-09-01 and 2026-09-02 dispatches are missing, because only rows whose exact usage block could be quoted were entered and “a run recalled but not quoted was left out rather than estimated”. This board does not estimate them either.
  3. The orchestrating session. Not captured at all: “only subagent dispatches return a usage block”. The true total is higher “by an unknown margin”.
  4. Anything on 2026-09-03. The ledger holds rows for 2026-09-01 and 2026-09-02 only. Today’s dispatches — including the one that produced this board — are not in it.
  5. Cost per finding. found is free text, not a count. Dividing tokens by defects would require assigning a number to a sentence, which is an interpretation and not in the data.
  6. Whether any of this was worth it. That is a judgement about the roadmap. This board reports what the ledger records; reading it belongs to Phase 11.

Assumptions

  • A-1. Every row in runs[] is accepted as entered. The file is hand-transcribed from dispatch usage blocks with no API behind it, so this board inherits any transcription error and cannot detect one.
  • A-2. duration_ms is treated as per-dispatch wall clock and the values are summed. If any two dispatches overlapped, the sum overstates elapsed time. The ledger does not record start timestamps, so overlap cannot be ruled out.
  • A-3. tokens is treated as one comparable unit across rows. The ledger does not break it into input, output or cache, so no cost in currency is derived here.
  • A-4. Plan is counted as an agent, because the agent field names it. It is not a row in CLAUDE.md’s routing table.
  • A-5. Colour values are read from token release 0.2.0, whose bone, ink and coral primitives carry a Gate A gate that a human has not yet cleared. If those values change, this board is regenerated rather than adjusted.

Claim format

Per CLAUDE.md and ADR-017, every figure above is a measurement, not testimony. It resolves to validation/agent-runs.json and a named field, and can be recomputed from that file alone. No [E-nnn] ID appears on this board and none is minted: research/evidence-ledger.json holds zero entries, no user was asked anything, and no person is quoted here. The one quoted passage is the ledger’s own the_rule string.
