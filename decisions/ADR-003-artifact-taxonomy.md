# ADR-003 — Artifact taxonomy and structure

**Status:** Accepted · 2026-08-25

## Decision
- `artifacts/` holds everything generated for a human to look at.
- **Every artifact is a directory.** No exceptions — uniformity removes a branch
  agents can get wrong, and provenance travels with the artifact when exported.
- Naming: `<workstream>/YYYY-MM-DD__<type>__<slug>__v<N>/`
- Contents: the artifact file(s), `manifest.json`, `validation.md`.
- Type must exist in `artifacts/_types.json` (**40 types**, five stages).
- Lifecycle: `draft → validated → in-review → approved → superseded → archived`.
  Versions are immutable; changes produce v2 and v1 becomes superseded.
- Superseded artifacts remain for provenance but are excluded from agent context.
- `_registry.json` and `ARTIFACTS.md` are generated by scanning, never hand-edited.
- **Nothing enters `artifacts/` until it passes validation.** Failures stay in `scratch/`.

## The membrane
A `component-spec` or `pattern-spec` in `artifacts/` is a **proposal**. It enters
`design-system/component-index.json` only by promotion — explicit human approval,
recorded as a new ADR. Promotion is the only path into the design system.

## Adaptation from the published standard
Eval workspaces sit under `validation/skill-evals/` rather than beside the skill
directory, to respect the boundary table. Internal structure is unchanged.
