# ADR-008 — Indexing layer, severity-ranked audit, and real CI

**Status:** Accepted · 2026-08-25
**Source:** Scrutiny of two live systems — `agentic-design-system-visualization.vercel.app`
(Cristian Morales) and `code-repo-iota.vercel.app` (Marta Conde).

## Context

Inspecting a shipping agentic design system (50 nodes, 6 layers, 78 components,
348 tokens, 657 relationships) exposed four weaknesses in Luma. Three were absences;
one was a defect in something already shipped.

## Finding 1 — Luma had no Indexing Layer

Their `.ai/index.toon` is loaded **once at session start** and encodes a usage
protocol: load once, keep in context, fetch detail on demand. Luma's agents would
have re-derived system structure every session — the exact cost their ARC trial
measures (65% → 100% accuracy, 26.5% → 0.04% variance, at +3.5% tokens).

Luma's CLAUDE.md already described three disclosure layers ("always on / on demand /
orchestration") but nothing implemented the first.

**Decision:** `validation/index-system.py` generates `.ai/index.json` (machine) and
`.ai/index.md` (cheap agent view): agents with tools and write-capability, artifact
types by stage and owner, ADRs, live SSOT state, and 150 typed relationships.
Generated by scanning; never hand-edited. CI fails if it is stale.

## Finding 2 — Gate B silently skipped checks

v1 skipped a check when its source of truth was absent, and said nothing. With
tokens.json empty (DS state RED), **raw hex passed silently**. An agent could not
distinguish "passed" from "never checked". That is a false sense of coverage — the
same failure as a named-but-empty layer.

**Decision:** Gate B v2 reports every skipped check with the reason, and prints
`SKIPPED is not PASSED` on every run.

## Finding 3 — Findings were binary and offered no fix

Their `/review-pr` returns Blocker / Error / Warning / Info **and reports which checks
it skipped**; their self-healing layer proposes the exact fix (which token replaces
which hardcoded value), not just the violation.

**Decision:** every finding in both Gate B and the system audit carries a severity and
a suggested fix. Only blocker and error block.

## Finding 4 — Enforcement layer 3 did not exist

CLAUDE.md claimed five enforcement layers. Layer 3 — "the same validators in CI" —
had **no implementation**. It was a sentence. Their `ci.yml` node is defined as
"automation that checks every change sent to the repository", and their `Docs &
workflow` layer sits *above* Foundations in the stack: documentation and automation
are layer one, not an afterthought.

**Decision:** `.github/workflows/ci.yml` runs `validation/audit-system.py` on every
push and pull request, plus JSON validation and staleness checks on both generated
indexes. A local hook can be disabled; CI cannot.

## Finding 5 — No system map

Their `architecture.md` is "a document that summarises the parts of the project and
how they relate". Luma had CLAUDE.md (plan and rules) but no map.

**Decision:** `architecture.md` at the repository root. CLAUDE.md operates the system;
architecture.md explains it.

## What was NOT adopted

- **Their inversion direction.** They are code-first with Figma mirroring. ADR-001
  keeps Figma as token owner after inversion. Unchanged.
- **Single-agent orchestration.** They run one agent invoking skills. Luma keeps the
  13-agent roster, routing table and per-agent tool gate (ADR-002).
- **The ARC benchmark as proof.** n=11, single system, self-reported, no published
  methodology; 100% accuracy and 0.04% variance are suspiciously clean. Treated as
  directional evidence only. It does corroborate ADR-005: they ran with and without
  infrastructure, which is the A/B baseline the eval standard requires.

## Consequence

All five enforcement layers now have an implementation. `architecture.md` documents
which file implements which layer, so a future empty layer is visible.
